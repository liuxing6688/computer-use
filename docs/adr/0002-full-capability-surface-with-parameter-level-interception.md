# 能力面全包，安全性靠参数级拦截而非削减能力

**Status**: accepted

本服务除桌面操控外，还自带 PowerShell 执行、文件操作、进程管理与 Office COM，尽管 Claude Code 原生已有 Bash 与文件工具。选择重复提供，是为了让模型在一个地方就能选到最优路径（能用 API/COM 完成的事不该用鼠标去点）。代价是攻击面变大，补偿是把安全做在**参数级拦截**上，而不是靠不给能力。

## 为什么这需要补偿

屏幕上的内容是别人写的。Agent 读取聊天窗口、网页或文档时，那些文字与用户的指令进入同一条上下文流，构成提示词注入的直接入口。作用域与危险动作分级防的是"模型点错"，防不了"模型被说服"——而被说服的模型手上正好握着 PowerShell。

## 拦截怎么做

- **PreToolUse hook** 负责常规拦截：它是 Claude Code 唯一能看到完整调用参数、且运行在模型之外的官方机制。仅靠 `permissions` 配置不行——它只认工具名，无法判断参数。
- **原生确认对话框**（由服务自己弹出）只用于外发动作与切换任务作用域这两类最不可挽回的动作。带外确认，模型无法参与。
- 明确拒绝"服务端返回需确认错误、让模型带 `confirmed=true` 重试"的方案：模型可以直接重试，等于没有拦截。
- 系统侧判定为读写分离 + PowerShell 命令白名单，且必须解析整条命令，不能只看开头的动词。

## 后果

屏幕上读到的内容须包裹在不可信标记中传给模型。安全判定逻辑（危险动作判定、命令解析、作用域计算）是全仓库唯一"写错了也看起来正常工作"的部分，必须测试先行，且验收要包含负向用例。

路由纪律有一个刻意的例外：浏览器虽然有 Playwright 这条更好的专用通道，一期仍要求用像素通道完成一项复杂网页任务并将其计入通过标准。目的是逼出像素通道在最吃力场景下的真实能力边界。
