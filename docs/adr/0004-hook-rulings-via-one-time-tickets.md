# 经人裁决的凭据：hook 交人之前留一次性裁决凭据，服务端只凭它执行危险动作

**Status**: accepted

PreToolUse hook 能把一次调用交给人（`permissionDecision: "ask"`），但它看不到人的答复：人同意，调用才抵达服务端；人拒绝，调用根本不会来。服务端于是无从区分"人同意过的危险调用"与"压根没经过 hook 的危险调用"（hook 没装、出错退出——Claude Code 对出错的 hook 照常放行）。若服务端对后者也放行，拦截就只在 hook 恰好生效时存在；若一律拒绝，危险动作就永远执行不了。

我们让 hook 在交人之前，为这一次调用留下一张**裁决凭据**：键是工具名与完整调用参数的规范化 JSON 的哈希，存在服务端与 hook 都够得到的数据目录里。服务端对判为危险的调用取走匹配的凭据才执行，一张凭据只放行一次，10 分钟后作废。拿不到凭据即拦截——包括模型把 `dangerous` 改成 `true` 原样重试的情形。

## 为什么这样可行

- 凭据只在 hook 决定交人时签发，而交人的调用只有经人同意才会抵达服务端：凭据被取走，就说明中间隔着一次人的裁决。
- 键覆盖全部参数：人批准的是"在截图 X 的 (x, y) 点击，意图是某某"，换一个坐标、改一个字的意图、多塞一个字段，都不是同一次调用。
- 失败方向是拒绝：hook 缺席、出错、参数规范化对不上、人确认得太晚，结果都是危险动作不执行，而不是执行。

## hook 只判一半

hook 只看得到调用参数，看不到截图，因此它只按模型自报判定（与服务端共用 `judge_call`）。落点附近 OCR 命中高危词、而模型自报不危险时，hook 放行，服务端拦下，并要求模型以 `dangerous: true` 重新调用——这一次经过 hook 交人。两条判据的并集就这样由两段拼成，而把 `dangerous` 设为 true 只会把调用送到人面前，不会让它自己通过。

## 明确接受的风险

- 凭据是数据目录里的普通文件。模型若借 Claude Code 自带的写文件或 Bash 工具伪造凭据，可以绕过这一层；那些工具有 Claude Code 自己的权限提示，且伪造需要算出参数哈希，属于"模型被说服并蓄意绕过"，不是"模型点错"。
- 人在 `bypassPermissions` 模式下运行 Claude Code 时，`ask` 是否仍然弹出确认由 Claude Code 决定，不在本服务的掌控之内。
